# 训练后发布决策规则

本文只决定在训练完成后发布哪一个既有 checkpoint，不要求修改模型代码。候选固定为：

- `M0`：未微调的 Qwen3-14B 基座；
- `M1`：阶段 1（全量清洗训练集）合并模型；
- `M2`：阶段 2（71 维均衡校准）合并模型。

三者必须在同一台机器、同一 vLLM 启动参数和官方生成协议下比较。禁止用不同 prompt、不同最大长度或多数投票成绩替代官方单次采样条件。正式比较使用 `temperature=0.6`、`top_p=0.95`、`max_tokens=8192`、`n=1`，种子固定为 `17/29/43`。

## 1. 数据边界

### 1.1 内部 dev

主决策集是故事簇隔离后的 `dev.jsonl`，共 375 条、129 个故事簇，且覆盖全部 71 个细维。三个一级能力在 dev 中分别有 92/149/134 条，不能直接用 375 条的自然微平均代表 A 榜。

每个 seed 分别计算心智化 `M`、社会互动 `I`、社会规范 `N`，再按由官方 A 榜反推的题量权重计算：

```text
W = (30/71) * M + (27/71) * I + (14/71) * N
  = 0.422535 * M + 0.380282 * I + 0.197183 * N
```

`W` 是训练后模型选择的主指标。71 维宏平均只用于发现长尾崩塌，不因单个细维只有少量 dev 样本而作为单独否决条件。

### 1.2 公开 213 条的使用边界

公开文件不是 213 条无争议真值。现有审计结果为：

| 分组 | 条数 | 允许用途 |
|---|---:|---|
| 字母与答案文本严格映射一致，且题型结构有效 | 136 | 报告 `public-safe accuracy`、解析率和 seed 稳定性 |
| 字母与答案文本冲突 | 60 | 只报告解析率、seed 一致性；未经人工裁决不得计准确率 |
| 答案文本无法唯一映射到选项 | 16 | 同上 |
| 需要人工复核的并集 | 77 | 单独保留，不自动进入任何发布分数 |

其中还有 5 条 `mcq_single` 却给出多个正确字母，已按保守策略排除。冲突类别存在重叠，因此不能简单把问题计数相加。

公开集的正确用法：

1. 在全部 213 条上计算与标签无关的解析率、超长截断率和三 seed 答案一致率。
2. 只在冻结的 136 条 `public_safe_dev.jsonl` 上计算准确率。
3. 公开集由 71 个故事各派生 Q1/Q2/Q3，统计误差应按故事簇理解，不能把 213 行当成 213 个独立样本。
4. 136 条是经“答案文字可精确映射”筛出的子集，可能偏向表述更直接、难度更低的样本，只能作方向验证，不能用其绝对分数预测 A 榜。
5. 一旦用公开样例调采样比例、选 checkpoint 或人工修标签，它就不再是独立测试集。当前版本应冻结，只允许一次最终比较。
6. 77 条冲突样例若要使用，须由两名评审在不知道模型预测的情况下独立裁决；不一致时由第三人裁决。裁决结果另行报告，不能覆盖官方原字段，也不能成为 `M2` 发布的唯一理由。

## 2. 每个候选必须报告的指标

对 `M0/M1/M2` 都生成同样的指标卡：

| 指标 | 定义 |
|---|---|
| `W_mean/W_std/W_min` | dev 官方权重分在 3 个 seed 上的均值、总体标准差和最差值 |
| `M/I/N mean` | dev 三类能力的 seed 均值 |
| `M/I/N std` | 三类能力的 seed 标准差 |
| `parse_min` | 每个 seed 解析率中的最小值 |
| `seed_consistency` | 同一样本在三个 seed 中答案完全相同的比例 |
| `majority_accuracy` | 三 seed 多数票准确率，只作诊断，不代替官方 `n=1` 分数 |
| `public_safe_mean` | 136 条安全子集准确率的 seed 均值 |
| `public_parse_min` | 全部 213 条的最差 seed 解析率 |
| `public_consistency` | 全部 213 条的三 seed 答案一致率 |

所有比较都必须是同一条样本、同一 seed 的配对比较。设：

```text
delta_s = W(M2, seed=s) - W(M1, seed=s)
delta_mean = mean(delta_s)
```

不要用两个模型各自最好的 seed 相减。

## 3. 硬门槛

任一候选未满足下列条件，不得作为正式发布模型：

| 项目 | 硬门槛 | 解释 |
|---|---:|---|
| 评测完整性 | dev `375*3`、public `213*3` 全部完成 | API 重试后的缺失不能当错误答案悄悄计入 |
| dev 解析率 | 每个 seed 至少 `374/375 = 99.73%` | 每个 seed 最多 1 条无有效最终框 |
| public 解析率 | 每个 seed 至少 `212/213 = 99.53%` | 使用全 213 条，标签冲突不影响该指标 |
| 长度截断 | 每个集合、每个 seed 至多 1 条 `finish_reason=length` | 避免正式评测出现“有效输出不足”或超时 |
| `W_std` | 不高于 1.25 个百分点 | 官方只采一次，均值高但随机性大的模型不可靠 |
| 单能力 seed 标准差 | `M/I/N` 均不高于 2.5 个百分点 | 小样本能力分允许比总体分更宽 |
| dev 三 seed 一致率 | 至少 88% | 低于此值说明温度 0.6 下答案集合不稳定 |
| public 三 seed 一致率 | 至少 85% | 公开题较长且含标签噪声，只用答案一致性 |

绿色目标比硬门槛更严格：`W_std <= 0.75pp`、单能力标准差 `<=1.5pp`、dev/public 一致率分别 `>=92%/90%`。

## 4. `M2` 相对 `M1` 的发布规则

### 4.1 绿色：发布两阶段模型 `M2`

必须同时满足：

1. `M2` 通过全部硬门槛；
2. `delta_mean >= +0.75pp`；
3. 三个 seed 中至少两个 `delta_s > 0`，且 `min(delta_s) >= -0.50pp`；
4. `M/I/N` 任一能力的 seed 均值相对 `M1` 不得下降超过 1.50pp；
5. `M2` 的 `W_std` 不得比 `M1` 增加超过 0.50pp，三 seed 一致率不得下降超过 2pp；
6. 136 条 public-safe 的均值不得比 `M1` 低超过 0.74pp，即最多相当于少对 1 条；多数票正确数不得少于 `M1`；
7. 全 213 条的解析率和一致率继续满足硬门槛。

这些条件把“均衡阶段带来真实增益”和“只在某个 seed 或带噪公开标签上碰巧变好”分开。

### 4.2 黄色：仅在稳定性明显改善时发布 `M2`

若 `+0.25pp <= delta_mean < +0.75pp`，只有在以下条件全部满足时才选择 `M2`：

- `M2` 无任何能力下降超过 1.0pp；
- public-safe 不少于 `M1` 两票多数的正确题数；
- dev 三 seed 一致率至少提高 3pp，或 `W_std` 至少下降 0.35pp；
- 三个 `delta_s` 均不低于 -0.50pp。

否则提升小于当前 dev/标签噪声可可靠区分的范围，发布 `M1`。

### 4.3 红色：拒绝 `M2`，回退 `M1`

出现任一项即回退：

- `delta_mean < +0.25pp`，且稳定性没有达到黄色规则的明显改善；
- 任一 seed 的 `delta_s < -1.0pp`；
- 任一一级能力均值下降超过 2.0pp；
- public-safe 在至少两个 seed 上少对 2 条或更多（136 条中约为 1.47pp）；
- 解析、截断、seed 方差或一致率未过硬门槛；
- `M2` 合并仓库无法在官方版本的 Transformers/vLLM 下完整启动。

## 5. `M1` 与基座 `M0` 的回退规则

对 `M1` 和 `M0` 使用同样的配对规则。`M1` 至少应满足：

- dev `W_mean >= M0 + 0.75pp`；
- 三类能力无一下降超过 1.5pp；
- public-safe 不比 `M0` 少对 1 条以上；
- 全部硬门槛通过。

若 `M1` 不满足，则发布已经通过完全相同仓库验证的 `M0`，不要因为已经花费训练成本而发布负增益模型。

最终回退顺序固定为：

```text
M2（绿色或满足黄色稳定性规则） -> M1（通过基座增益规则） -> M0
```

每个版本使用不同的不可变 tag/commit。不得覆盖已验证 revision。

## 6. 与当前 A 榜的量化联系

官方快照第一名为 67.3239%，第二名为 64.2254%，差 3.0985pp；明确标为 `qwen3-14b-ft` 的提交为 64.1690%，距第一名 3.1549pp。按反推的 1,775 题计算，两者都约差 55–56 道题。Qwen3-8B 官方基线 61.0141%，距第一名 6.3098pp，约 112 道题。

本地 dev 的绝对分数不能直接校准为 A 榜绝对分，只能用于 `M0/M1/M2` 的配对排序。首个官方有效成绩到手后按以下方式使用第二个日额度：

- 若 `M1` 已提交且 `M2` 为绿色，第二次提交 `M2`；
- 若 `M2` 仅黄色，而 `M1` 官方成绩已达到或超过 64.23%，保留 `M1`，除非 `M2` 明确修复官方最弱能力且其余能力无回退；
- 若官方成绩低于 63.9%，先确认解析率、模型启动配置及分能力是否与本地排序一致，不因公开 136 条的偶然优势盲目切模型；
- 达到 67.4% 只表示超过该时间点的榜首快照，不是稳定夺冠线，仍须保留完全复现的 revision 供 B 榜和技术复核。

## 7. 20B 与 14.8B 的口径

官方赛事页、参赛指南和提交表单一致规定“开放权重且实际参数量不超过 20B”，worker 下载后会重新核验。分享页中的 14.8B 应视为当前 Qwen3-14B 候选模型的实际规模或本方案预算，而不是赛事上限；若分享页把 14.8B 写成上限，则以官方 20B 规则为准。

当前候选约 14.8B，已在官方 20B 资格范围内。训练后决策不应为了“用满 20B”临时更换架构；vLLM 兼容性、推理时延和已验证的配对增益优先级更高。
